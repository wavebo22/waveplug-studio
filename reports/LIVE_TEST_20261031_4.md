### 3.2 0.1.2 安装

用户明确回复“已保存并退出”后，两次安装前均检查无 Photoshop.exe。

1. C:\Users\WAVE 工作目录、非提升权限 UPIA：原文 `Failed to install, status = -432!`；/list all 仍 Enabled 0.1.1。
2. 保持同一 CCX 和 C 盘工作目录，使用既有 AgentDock 提升权限通道：原文 `Installation Successful ... for all users`；/list all 明确显示：

```text
Enabled    OpenLayer              0.37.0
Enabled    WavePlug - PS AI Studio 0.6.1
Enabled    WavePlug Studio         0.1.2
```

证据：
- `install_012_20261031_4.log`：首次失败及列表。
- `adobe_non_elevated_20261031_4.log`：Adobe 用户日志记载 non elevated 与 -432。

- `install_012_elevated_readable_20261031_4.log`：上述英文日志移除 NUL 后的可读副本。
- `adobe_elevated_20261031_4.log`：Adobe 系统日志原文 Running elevated，handleInstallExtension status 0。

Adobe 员工发布的[错误码表](https://community.adobe.com/questions-628/exmancmd-upia-error-codes-as-of-oct-31-2022-685810)将 -432 定义为 EXMAN_FAILED_OPERATION_NOT_ALLOWED。**结合本机安装范围、权限日志与对照结果，权限/安装范围不匹配是本次失败的主要解释**；切换执行通道也改变了部分环境，因此不声称已经隔离出 UPIA 内部的精确拒绝分支。

另一次沙箱内的 /list all 因无法初始化 Adobe logger 返回 -164 并挂起，已终止本轮创建的该 UPIA 进程，改为获授权的沙箱外执行后可正常列出。未终止 Photoshop，未修改 Adobe 数据库或注册表。

### 3.4 COM / Photoshop MCP

- Photoshop 安装前运行令牌为 **非管理员 Medium**，已直接读取 Photoshop 进程令牌，不是从代理权限推测。
- 同为 Medium 的调用者，只取已运行 COM 对象（CLSIDFromProgID + GetActiveObject，不启动应用）返回：
  `操作无法使用 (0x800401E3 (MK_E_UNAVAILABLE))`。
- 只读注册表：Photoshop.Application 的 CurVer 是 Photoshop.Application.200；CLSID `{2682BB05-0A88-430F-8614-EE4E60E6D916}`，LocalServer32 指向 `D:\Art\Adobe\Adobe Photoshop 2026\Photoshop.exe /Automation`。注册存在不等于 COM 激活可用。
- Photoshop MCP 执行仅返回版本与文档数的只读脚本，工具返回 `extendscript_timeout`，原文：
  `Error executing custom script: Script execution timeout The MCP wait ended; Photoshop may still be running that script. Call photoshop_ping until it succeeds before more edits. Retry once with timeout_ms.`
- 本轮没有重新得到“ActiveX 部件不能创建对象”的原文。COM 自动化 **未验证可用**；不能将其归因于 Photoshop 以管理员身份运行。用户随后自行退出 Photoshop，后续未通过该 MCP 发起编辑。启动后应先 ping 再决定是否继续使用。
