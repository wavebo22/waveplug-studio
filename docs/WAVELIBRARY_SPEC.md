## 1. 定位

WaveLibrary 是 WavePlug 的素材管理模块，参考 After Effects、Premiere Pro 的项目素材管理方式。它管理一个设计项目用到的全部外部资源：图片、智能对象源文件、生成变体、PDF、Office / WPS 文档、文案、提示词，以及其他任意格式的文件。

分工：

- Photoshop：画布和图层编辑。
- WavePlug：生成和交互。
- WaveLibrary：素材的长期存储、关联、版本管理和项目交付。

核心关系：

- Photoshop 图层 = 素材在画布上的实例。
- 链接智能对象 = Photoshop 和外部素材之间的连接。
- WaveLibrary 文件夹 = 素材的真实存储。
- `asset.json` = 一个资产和它的变体的记录。

核心原则：

1. 素材是磁盘上的真实文件，不依赖 Photoshop 图层而存在。
2. 变体是真实文件，不再用 Photoshop 图层组模拟。
3. 非破坏：删除图层不删文件，删除文件不删图层，任何操作都不覆盖原始素材。
4. **Photoshop 里的链接是唯一事实**：图层当前用哪个文件，以图层的实际链接路径为准，不另外存一份（见第 7.1 节）。

## 2. 素材库的位置和文档关联

### 2.1 位置【已确认】

素材库是 PSD / PSB **同级目录下名字固定的文件夹 `WaveLibrary/`**，不再用 `<文档名>.WaveLibrary`。

```text
D:\Project\
├── 主视觉.psd
├── 主视觉_v2.psd
├── 延展_横版.psd
└── WaveLibrary\
```

结果：

- 同一目录下的所有 PSD / PSB 共用一个素材库。客户文档、文案只存一份。
- 同目录另存为（`主视觉_v2.psd`）、文档改名，都继续用同一个库，不需要任何处理。
- 文档和 `WaveLibrary/` 一起移动时，Photoshop 自己按相对路径恢复链接【需 POC】。

### 2.2 库 ID

固定名字带来一个问题：把 PSD 另存到另一个恰好也有 `WaveLibrary/` 的目录，会把别人的库当成自己的。所以：

- 建库时生成一个库 ID，写进 `library.json`。
- 文档第一次使用素材库时，把库 ID 写进 PSD 的文档元数据（XMP 或文件简介字段，具体用哪个实现时定）。
- 打开文档时比较两边的 ID。

| 文档里的 ID | 同级 `WaveLibrary/` | 结果 |
|---|---|---|
| 没有 | 没有 | 没有素材库，第一次添加内容时创建 |
| 没有 | 有 | 提示标签「此目录已有素材库」，用户点一下加入 |
| 有 | 有，ID 相同 | 正常 |
| 有 | 有，ID 不同 | 提示标签「另存为其他路径」，见 2.4 |
| 有 | 没有 | 提示标签「另存为其他路径」或「素材库丢失」，见 2.4 |

### 2.3 素材属于哪个文档

库是多个文档共用的，所以「这个素材被谁用」不靠文件夹区分，靠**扫描文档里的链接智能对象路径**得出。`library.json` 的 `documents[]` 只记录加入过这个库的文档（名称、最后一次看到的相对路径），用于显示和打包，不作为关联的依据。

### 2.4 特殊情况

**未保存的文档**【已确认】

未保存的文档没有同级目录，建不了库。V1.0 的做法是禁用，这会让「新建文档直接生成」的现有流程倒退。改为：

- 不在文档旁边创建素材库，不复制用户的任何文件。
- 素材库页面显示提示标签：「文档尚未保存，请先保存文档以确定素材库位置。」
- **生成功能照常可用**【已确认】：结果写进 WavePlug 数据文件夹里的**临时素材库** `<WavePlug 数据文件夹>\unsaved\<文档 ID>\`（结构和正式素材库相同），图层链接到那里，变体照常切换。变体栏显示「未保存，变体暂存在临时素材库」。
- 文档第一次保存时，提示「把临时素材移入素材库」：把用到的资产移到文档旁边的 `WaveLibrary/`，并重新链接。不移入的话，图层继续链接临时素材库，提示标签保持。
- 没保存就关掉的文档，它的临时素材库由 WavePlug 程序统一清理（和缓存一起显示占用），清理前提示。
- 文档里原来就有的嵌入式智能对象不受影响，保存后可以照常外置化（第 6 节）。
- 备选：如果临时素材库在 POC 里出问题，退回为未保存时只保留一张嵌入式智能对象结果。

**另存到其他路径**【已确认：不自动复制】

例：`D:\Project\A.psd` 另存为 `E:\Delivery\A.psd`。此时新文档的图层仍然用绝对路径链接着 `D:\Project\WaveLibrary\` 里的文件。

- 显示提示标签，不自动做任何事。
- 原文档和原素材库不受影响。
- 用户三选一：
  1. **继续使用原素材库**：什么都不动，新文档依赖原路径。标签改为「使用外部素材库：D:\Project\WaveLibrary」。
  2. **新建空素材库**：在新位置建空库。已有图层仍链接原库，这些图层显示「外部链接」状态，可以逐个或批量归档进来。
  3. **收集到新素材库**【已确认】：把当前文档用到的资产复制到新库并重新链接，原库不动。默认复制**整个资产文件夹**（含全部变体），到了新位置仍然可以切换变体；可选「只收集在用的文件」，体积小，适合交付（和第 11 节「只收集当前文档用到的素材」是同一个功能）。这是用户点了才执行的复制，不违反「不自动复制」。

**文档移动或改名**

- 改名：没有影响（库名固定、ID 在文档里）。
- 和 `WaveLibrary/` 一起移动：自动识别。
- 只移动了文档：按「另存到其他路径」处理。
- 任何情况都不重新生成库 ID 和资产 ID。

## 3. 目录结构

```text
WaveLibrary/
│
├── library.json                 库 ID、格式版本、加入过的文档、编号计数
│
├── 01_素材/                     ← 托管区
│   ├── asset_001_背景/
│   │   ├── asset.json           这个资产和它全部变体的记录
│   │   ├── source.psb           原始文件（「变体 0」）
│   │   └── variants/
│   │       ├── v0001.png
│   │       ├── v0002.png
│   │       └── v0003.png
│   └── asset_002_产品/
│
├── 02_文档/                     ← 自由区
│   ├── 客户需求.pdf
│   └── 报价单.xlsx
│
├── 03_文案/                     ← 自由区
│   ├── 主视觉标题.md
│   └── 生成提示词.md
│
├── 04_导出/                     ← 自由区
│
├── （用户自己建的文件夹）         ← 自由区
│
└── .trash/                      库内回收站
```

缓存（缩略图、预览、索引）不放在素材库里，见 3.5。

### 3.1 托管区和自由区【已确认】

V1.0 写「用户可以在素材库内自由移动、重命名、删除文件」，这和链接管理冲突：在资源管理器里改一个变体的文件名，Photoshop 的链接就断了。所以分成两个区。

**托管区（`01_素材/`）**

- 只通过 WavePlug 操作。改名、移动、删除由 WavePlug 完成，需要时同时重新链接图层。
- 用户仍然可以在资源管理器里看到和打开这些文件，但在外面做的改动，WavePlug 只报告状态（已修改 / 丢失），不猜测、不自动修复。
- 文件名由系统编号，不会重名覆盖。

**自由区（其余全部）**

- 文件系统就是事实。WavePlug 直接读目录显示，**不写进任何索引**。
- 用户在资源管理器里随便增删改，刷新后就是最新的。
- 任意格式都可以放。

### 3.2 相对 V1.0 的结构改动【已确认】

- **`01_素材` 和 `04_变体` 合并**。V1.0 是两棵按资产 ID 平行的目录树，要一直保持同步。现在一个资产一个文件夹，源文件和变体在一起。
- **原始文件算「变体 0」**，在变体栏里排第一个，可以切回去。V1.0 没有写怎么回到原图。
- **只有一份记录**。V1.0 有 `library.json`、`asset.json`、`variants.json` 三份互相重叠。现在每个资产的 `asset.json` 是唯一事实；`library.json` 只有库级信息，损坏了可以从各个 `asset.json` 重建。代价是打开素材库要读每个 `asset.json`，资产多、库在 NAS 上时会慢一些，用 3.5 的索引缓存加速。用户接受这个代价，换来文件整理和链接的可靠。
- 回收站是 `.trash/`。缓存不放在素材库里（3.5）。

### 3.3 文件规则

- 所有路径在 JSON 里都存**相对于 `WaveLibrary/` 的路径**，用 `/` 分隔。
- 资产文件夹名是 `asset_<编号>_<建立时的名称>`。之后在 WavePlug 里改资产的显示名，只改 `asset.json`，**不改文件夹名**（改了就要重新链接所有图层）。
- 编号从 `library.json` 的计数器取，只增不减，删除后不复用。
- JSON 写入一律「写到 `.new` 再改名」，不在原文件上直接改。库经常放在 NAS / 网络共享上，写一半断开不能留下坏文件。
- JSON 带 `schemaVersion`。
- 导入文件默认复制，不移动原文件。

### 3.4 `asset.json` 的内容

```jsonc
{
  "schemaVersion": 1,
  "id": "asset_001",
  "name": "背景",
  "kind": "imported",            // imported：外置化或导入的；generated：生成时新建的，source 是第一张生成结果（7.2）；derived：放大当前图层得到的（7.2.2）
  "source": { "file": "source.psb", "width": 4000, "height": 3000, "size": 52428800, "mtime": "…" },
  "derivedFrom": null,           // 放大当前图层：{ "asset": "asset_001", "variant": "v0002", "op": "upscale", "scale": 2 }
  "outpaint": null,              // 扩图资产：{ "pads": [左, 上, 右, 下], "canvas": [扩展前宽, 扩展前高] }（7.2.3）
  "variants": [
    {
      "id": "v0001",
      "file": "variants/v0001.png",
      "width": 4000, "height": 3000, "size": 9123456, "mtime": "…",
      "createdAt": "2026-11-16T12:00:00+08:00",
      "prompt": "…", "negative": "…",
      "model": "…", "workflow": "…",
      "params": { "seed": 123, "…": "…" },
      "references": ["asset_002/v0003"],
      "from": "source"            // 这个变体是从哪个版本生成的
    }
  ]
}
```

**不记录**「哪个图层当前用哪个变体」，原因见 7.1。`size` 和 `mtime` 用来判断文件是否在外部被改过。

### 3.5 缓存【已确认】

缩略图、预览图、打开加速用的汇总索引，都放在 **WavePlug 自己的数据文件夹**里，不放进素材库：

```text
<WavePlug 数据文件夹>\cache\library\<库 ID>\
├── index.json        各 asset.json 的汇总，打开时先读它
├── thumbnails\
└── previews\
```

WavePlug 数据文件夹就是外置程序用的那个（安装版是 `<安装文件夹>\data`，否则 `%LOCALAPPDATA%\WavePlug`，见 `native/overlay/src/paths.rs`）。

- 所有素材库的缓存集中在一处，WavePlug 程序里可以统一查看占用、一键清理。
- 素材库文件夹里只有真实素材，打包、交付时不用排除缓存。
- 缓存全部可以重建。`index.json` 和实际的 `asset.json` 对不上（`mtime` 变了、文件多了或少了）时，以 `asset.json` 为准并重建。
- 同一个素材库在两台电脑上打开（例如放在 NAS 上），各自有各自的缓存，互不影响。

## 4. 素材添加与管理

添加方式：

1. 从 Windows 资源管理器拖入。
2. 从「WavePlug 图层」面板把图层拖入（智能对象走第 6 节的外置化）。**只支持这个面板**，不考虑 Photoshop 自带的图层面板，也不另加「归档所选图层」按钮【已确认】。
3. 「添加文件」按钮选择文件。
4. 粘贴剪贴板里的文字（成为一条文案）。
5. 新建文案。
6. 新建文件夹（自由区）。

管理功能：

- 文件夹新建、删除、重命名（自由区）。
- 文件移动、复制、删除。
- 多选和批量操作。
- 搜索、按类型过滤。
- 列表 / 缩略图两种显示。
- 打开所在目录。
- 用系统默认软件打开。
- 查看文件信息。
- 图片缩略图。

PDF、Office、WPS 等只负责存放、显示和调用外部软件打开，不做内置编辑。

缩略图：PNG / JPG 直接显示；PSD / PSB 等在归档时让 Photoshop 导出一张预览存进缓存（3.5）。缩略图在入库时生成，不在浏览时现算。

## 5. 文案

文案是素材库的独立组成部分，不是普通附件。存在自由区的 `03_文案/`，每条一个 `.md`（或 `.txt`）文件。

- 直接粘贴文字成为新文案。
- 新建多条。
- 双击编辑，自动保存。
- 一键复制全文。
- 搜索（文件名和内容）。
- 类型（标题 / 正文 / 备注 / 提示词…）：写在文件开头的一行标记里，文件用别的编辑器打开仍然是普通文本。

用途：客户提供的文案、设计说明、修改意见、生图提示词、项目记录。

## 6. 智能对象外置化

### 6.1 嵌入式智能对象 → 素材库

1. 画布上的图层保留。
2. 在 `01_素材/` 建资产文件夹。
3. 把智能对象的原始内容导出为 `source.<原格式>`（`placedLayerExportContents`，保留原格式：psb / png / jpg / ai…）。
4. 把图层从嵌入转成链接，指向这个文件（`placedLayerConvertToLinked`）【需 POC】。
5. 写 `asset.json`。

必须保留：位置、名称、缩放和旋转、变换、蒙版、图层样式、智能滤镜，以及其他编辑属性【需 POC：逐项确认】。

整个过程是一步历史记录（放在 `step()` 里）。撤销后图层回到嵌入状态，素材库里的文件保留，成为「未关联」。

### 6.2 库外的链接智能对象 → 素材库

1. 把链接的原文件复制进素材库。原文件不移动、不删除。
2. 图层重新链接到库里的副本（`placedLayerRelinkToFile`，代码里已有）。
3. 写 `asset.json`。

完成后当前 PSD 不再依赖原来那个目录。

### 6.3 一个智能对象有多个图层实例【已确认】

Photoshop 里复制出来的智能对象图层共享同一份内容。拖入其中一个时，如果文档里还有别的图层共享它，**弹出确认**：

- **全部转换**：所有共享的图层一起变成链接，指向同一个资产。
- **只转换这一个**：这个图层先和其他实例分开，再单独转换。
- 带「本次操作都这样处理」的勾选，避免多选拖入时连续弹窗。

实现（POC P0-2 已验证）：

- 嵌入式：「只转换这一个」直接对这个图层执行转为链接，共享内容的其他图层不受影响，仍是嵌入。「全部转换」先转换其中一个，再把其余几个重新链接到同一个文件（对嵌入图层直接重新链接就会变成链接）。
- 已经是链接的：链接同一个文件的图层在 Photoshop 里本来就绑在一起（7.3），只能一起归档，不弹出选择，完成后提示一共处理了几个图层。

### 6.4 多选

- 按图层原有顺序处理。
- 每个对象各自的位置和属性都保留。
- 每个对象一个资产 ID（共享同一内容的图层按 6.3 处理，共用一个资产）。
- 一个失败不影响其他。
- 结束后显示成功和失败的数量，失败的列出原因。

### 6.5 不处理的情况

- **非智能对象图层**不自动转换。拖入时提示，用户可以明确选择「转换为智能对象并归档」。
- **智能对象内部嵌套的智能对象**：V1 不处理，只管文档顶层能看到的图层（包括组和画板里的）。

## 7. 变体

取消用 Photoshop 图层组模拟变体的方案，统一为外部文件 + 链接智能对象。画布上只有实际使用的那一个链接智能对象。

### 7.1 当前变体不存进 JSON【已确认】

「图层 X 当前用变体 N」这条信息**不写进任何 JSON**。每次需要时，读图层的实际链接路径，路径是 `…/asset_001_背景/variants/v0002.png` 就是变体 02。

原因：Photoshop 的撤销管不到磁盘上的 JSON。

1. 图层链接着 `v0002.png`，JSON 记「当前 = 02」。
2. 点变体 03，图层重新链接到 `v0003.png`，JSON 改成 03。
3. 在 Photoshop 里 Ctrl+Z，链接回到 `v0002.png`，JSON 仍然是 03。
4. 画布显示 02，变体栏高亮 03。

历史记录面板跳回旧状态、不保存就关闭、复制图层、另存为副本，都会出同样的错位。以链接路径为准就不会。

附带结果：V1.0 第 7.5 节「一个资产被多个图层引用、各用各的变体」不需要额外的数据结构，每个图层的链接路径本身就是它的状态。

### 7.2 生成流程

1. 确定资产：
   - 当前图层链接着素材库里的文件 → 用它的资产。
   - 当前图层是嵌入式智能对象 → 先外置化（6.1），再用新资产。
   - 没有对应图层（框选区域生成、文生图）→ 新建一个 `kind: "generated"` 的资产，**本次生成的第一张结果作为 `source`（变体 0）**，同一次生成的其余结果是 v0001、v0002…。之后对这个资产再生成，都追加为新变体。对同一个选区连续生成，得到的是一个资产带多个变体，不是多个资产【已确认】。
   - 选中的是普通像素图层（不是智能对象）→ 先把它转成素材，再按第一条生成变体【已确认】，见 7.2.1。
   - 放大、扩图（结果和输入尺寸不同）→ 新建资产、新建图层，两者分开处理，见 7.2.2、7.2.3。
2. 结果存为该资产 `variants/` 下的新文件，编号递增，**不覆盖旧文件**。
3. 在 `asset.json` 里追加变体记录。
4. 把图层重新链接到新文件（没有图层的情况：置入为链接智能对象）。
5. 刷新变体栏。

文档未保存时不走这个流程，见 2.4。

生成时需要资产的像素（图生图）可以直接读文件，不必再从 Photoshop 导出。

#### 7.2.1 普通像素图层做图生图【已确认】

像素图层本身就是主体，所以转换：

- 像素导出为新资产的 `source.png`。
- 图层原地换成链接到这个文件的链接智能对象，不另外多出一个图层；位置、名称、蒙版、图层样式保留【需 POC：原地替换能否全部保留，包括剪贴蒙版关系】。
- 生成结果是这个资产的变体，切换时重新链接这个图层。
- 转换和第一次生成在同一步历史记录里。撤销后图层回到像素图层，素材库里已经写出的文件保留（未关联）。

#### 7.2.2 放大【已确认：新建图层】

放大和扩图的共同规则：

- 结果和输入尺寸不同，**不是原资产的变体**，而是新资产。第一张结果是新资产的 `source`，同一次生成的其余结果是它的变体（同 7.2）。
- 结果放在**新图层**上，原图层保留。
- 只在生成完成时计算一次摆放位置，之后在新资产里切换变体，尺寸都一样。
- 用户手动加进某个资产的文件，尺寸不同时也作为新资产，不作为变体。

现有的放大有两种（`generate.ts` 的 `runUpscale`），分开处理。

**放大当前图层**（现在：每个图层放大成一个智能对象，放在它上面）

- 新资产 `kind: "derived"`，`derivedFrom` 记录原资产、原变体、`op: "upscale"`、倍数。原图层还不是素材库里的链接对象时，先按 6.1 / 7.2.1 转成素材。
- 输入是原资产文件本身的像素（不含蒙版、样式、变换），输出 = 原尺寸 × 倍数。
- 新图层是链接到新资产的链接智能对象，放在原图层正上方。变换复制原图层的（位置、旋转、斜切），缩放除以倍数，所以画布上的范围和原图层完全重合，只是更清晰。
- 蒙版、图层样式、混合模式、不透明度、剪贴蒙版关系复制到新图层【需 POC】。
- 素材库里，新资产显示为原资产的「衍生」，两者可以互相跳转。
- 原图层保持可见，不自动隐藏，由用户自己对比校对【已确认】。

**放大选区或整张画布**（现在：可见图层合并后放大，结果放进一个新文档，原文档不动）

- 输入是合并后的画面，不对应某个资产，新资产 `kind: "generated"`。
- 结果放进新文档的临时素材库（2.4），新文档保存时再移入它自己的素材库【已确认】。

#### 7.2.3 扩图【已确认：新建图层】

现在的扩图（`generate.ts` 的 `runOutpaint`）作用于**整张画布**：可见图层合并后的画面发出去，扩展画布，结果放进扩图图层组，中间原有的部分用带羽化接缝的蒙版透出下面的原图层。它的输入不是某个图层，所以和放大当前图层不同，没有「原资产」。

新方案：

- 新资产 `kind: "generated"`，第一张结果是 `source`。`asset.json` 的 `outpaint` 记录四边各扩了多少和扩展前的画布尺寸。
- 扩展画布和新建图层在同一步历史记录里。新图层是链接智能对象，覆盖扩展后的整张画布，放在最上方。
- 接缝蒙版是新图层的**图层蒙版**，不写进资产文件，所以切换变体时蒙版不变，原图层照样从中间透出来。
- 继续扩图（现在的「在已有扩图上继续」）：四边扩展量和画布尺寸都和记录一致时，结果追加为这个资产的变体；不一致（例如画布被裁剪过）时提示新建扩图，和现在一样。

### 7.3 切换变体

点变体缩略图：

- 当前图层重新链接到那个变体文件。
- 不新建图层，不新建图层组。
- 一步历史记录。

**同一资产的变体尺寸一致**【已确认】：同一个资产里的变体都和 `source` 尺寸相同，所以切换变体不会遇到尺寸问题，图层在画布上的范围不变。放大、扩图另立资产（7.2.2、7.2.3）。

**链接同一个文件的图层绑在一起（沿用 Photoshop 的逻辑）**【已确认】

POC P0-2 发现：Photoshop 按文件路径给链接图层分组。链接同一路径的图层，重新链接任何一个都会全部跟着变，并且从此绑在一起。WaveLibrary 不绕开这一点：

- 两个图层用不同的变体时互相独立；只要用到同一个变体文件，就和 Photoshop 一样绑在一起，之后切换其中一个，其他的一起切换。Ctrl+J 复制出来的链接图层也一样。
- 变体栏标出「N 个图层绑定」，切换前让用户知道会影响几个图层。
- 不做实例路径、硬链接，也不提供「设为独立」。以后需要时，POC 里有验证过的做法可以参考（`poc/WAVELIBRARY_POC.md` P0-2 g、h、i）。

**速度**【需 POC】：现在切换变体是改图层可见性，几乎没有延迟；改成重新链接大文件可能明显变慢。悬停预览只用缩略图，不触发重新链接。

### 7.4 生成记录

每个变体在 `asset.json` 里保存：提示词、反向提示词、模型、工作流、生成时间、参数、参考图、文件路径、来源版本（见 3.4）。

### 7.5 删除和清理【已确认】

- 删除变体：文件移到 `.trash/`，不直接删除。否则在 Photoshop 里撤销回去，链接会指向一个不存在的文件。
- 「清理未使用的变体」：列出当前目录已知文档都没有链接的变体，显示占用空间，用户确认后移入回收站。
- 回收站页面有「清空回收站」按钮，随时可以主动清理。这是唯一真正删除文件的操作，要二次确认。
- **关闭文档时提示清理**：关闭文档后，这个素材库的回收站里有文件时，弹出「回收站有 N 个文件，共 X MB，是否清空？」，带「不再提示」。回收站是空的就不弹。
  - UXP 拦不住关闭，提示在文档关闭之后出现。素材库在磁盘上，不受影响。
  - 退出 Photoshop 时插件来不及弹窗，改由 WavePlug 程序在下次启动时提示。
  - 只提示回收站，不列出未使用的变体；未使用的变体在素材库里手动清理。
- 判断变体是否「未使用」，要知道同目录所有文档的链接，但没打开的 PSD 读不到。所以每个文档保存和关闭时，把它用到的文件写进 `library.json` 的 `documents[].uses`。这份记录只用来给清理提建议，被误判的文件也只是进回收站，不会直接删除。

### 7.6 色彩【已确认：尽量保留原色彩】

目的是以后能回溯到每个文件当初的样子，所以素材库里的文件**不做色彩转换**：

- 变体按生成结果原样保存，保留生成时的位深和色彩配置文件（ComfyUI 的输出一般是 sRGB 8 位），PNG 里嵌入配置文件。
- 导入、外置化的源文件原样复制或导出，保留原格式、位深、色彩模式和配置文件。
- 文档是 CMYK、16 位或其他色彩空间时，Photoshop 显示链接对象时会自己转换，但文件本身不改。变体信息里标出文件和文档的差异，例如「文件 sRGB 8 位，文档 CMYK」。

## 8. 同步

### 8.1 打开文档时

1. 识别当前文档，读它的库 ID。
2. 找同级 `WaveLibrary/`，按 2.2 的表判断。
3. 读 `library.json` 和各个 `asset.json`。
4. 检查托管区的文件是否存在、`size` / `mtime` 是否变了。
5. 扫描自由区目录。
6. 读文档里所有链接智能对象的路径（只读需要的属性，**不对图层做不带 `_property` 的 `get`**）。
7. 按路径把图层和资产、变体对上。
8. 刷新素材列表和变体栏。

### 8.2 其他触发

- 切换文档。
- 图层新增、删除、移动（已有的图层事件监听）。
- 生成新变体。
- 外部文件变化：UXP 没有文件监听，用「面板可见时定时检查 + 手动刷新按钮」，或交给外置框架监听。实现时选一种。

### 8.3 状态

| 状态 | 含义 |
|---|---|
| 正常 | 文件在，记录一致 |
| 已使用 | 当前文档有图层链接着它 |
| 未关联 | 文件在，但当前目录已知的文档都没有链接它 |
| 已修改 | 文件在外部被改过（`size` / `mtime` 和记录不同） |
| 丢失 | 记录里有，文件不在 |
| 外部链接 | 图层链接着素材库以外的文件（或另一个素材库） |

丢失时提供「重新定位」，不自动删除图层，也不自动删除记录。

## 9. 修改与删除规则

- 删除 Photoshop 图层，不删素材库里的文件。
- 删除素材文件，不删 Photoshop 图层。
- 托管区文件在外部被移动 → 标记丢失，提示重新定位。
- 托管区文件在外部被修改 → 标记已修改。
- 不覆盖原始素材。
- Photoshop 里撤销，不删除已经生成的文件。
- 清理缓存只删 WavePlug 数据文件夹里的缓存（3.5），不碰素材库。
- 删除文件一律先进 `.trash/`。
- 删除整个素材库之前，提示有哪些文档的哪些图层会丢失链接。

## 10. 界面

WaveLibrary 是 WavePlug 里的一个独立页面，和 WaveLayer、生成模块联动。写界面前读 [`UI_DESIGN_SYSTEM.md`](UI_DESIGN_SYSTEM.md)。

**提示标签**（页面顶部，按 2.2 / 2.4 的情况显示其中一个）：未保存、此目录已有素材库、另存为其他路径、使用外部素材库、素材库丢失。

**工具栏**：搜索框、类型过滤、列表 / 缩略图切换、添加文件、新建文件夹、刷新。

**分类**：全部、素材、文档、文案、用户自定义文件夹、回收站。变体不单独成一类，在素材里点开资产查看。

**内容**：

- 图片素材：缩略图，角标显示状态和变体数量。
- 文档：类型图标、名称、大小。
- 文案：标题和内容预览。
- 变体：缩略图、编号、生成时间；当前图层正在用的那个高亮。

**交互**：

- 从素材库拖图片到画布：置入为链接智能对象（`placeEvent` 加 `linked: true`）。
- 从「WavePlug 图层」面板拖入智能对象：外置化。
- 双击文档：系统默认软件打开。
- 双击文案：编辑。
- 右键：文件管理菜单。
- 多选和批量操作。

## 11. 导出（后续）

统一的导出入口：

1. **完整项目打包**：PSD / PSB、全部被引用的链接文件、原始素材、全部变体、文案、附件、JSON 记录。
2. **只收集当前文档用到的素材**（和 2.4 的「收集到新素材库」是同一个功能）。
3. **嵌入全部并另存交付版**【已确认】：把所有链接转回嵌入，另存一个不依赖素材库的 PSD。只发一个 PSD 给客户或印厂时用这个，比打包文件夹更常用。
4. **变体批量导出**：选中一个或多个资产，导出全部或指定变体。
5. **文案导出**。
6. **资源清单**：文件名、类型、路径、关联状态。

## 12. 旧文档【已确认：不迁移、不兼容】

现有文档里的「AI 填充图层组」本来就是用图层组模拟的变体，不做迁移，也不做兼容：

- 新版本不再识别旧的变体图层组。打开旧文档时，它们就是普通的图层组。
- 现有的变体图层组代码（切换变体、删除变体、变体栏、外置面板的变体页）在一期删掉，由新方案替换。
- 新生成的内容：文档已保存时走素材库；未保存时走临时素材库（2.4）。

## 15. 分期

1. **一期**：建库和文档关联（第 2、3 节）、智能对象外置化（第 6 节）、变体文件化和切换（第 7 节）、删掉旧的变体图层组代码（第 12 节）。这一期决定数据格式。
2. **二期**：文件、文案、附件的管理界面（第 4、5、10 节）。
3. **三期**：状态同步、重新定位（第 8 节）、导出（第 11 节）。

## 16. 验收要求

1. 素材库是独立于 Photoshop 图层的真实文件。
2. 自由区可以放任意格式的文件。
3. 文案可以直接粘贴、编辑、保存。
4. 智能对象归档后画布图层保留，并变成链接智能对象，原有属性不变。
5. 库外链接对象归档时复制原文件，不移动、不删除。
6. 变体全部是外部文件，不再有变体图层组。
7. 生成结果自动存进对应资产的 `variants/`。
8. 切换变体通过重新链接完成，并且在 Photoshop 里撤销后变体栏的高亮仍然正确。
9. 打开文档时自动读取素材库并对上图层。
10. 文件丢失、被修改、被移动时有明确的状态。
11. 删除图层不会删除素材。
12. 未保存、另存到其他路径各有独立的提示标签，不自动复制素材库。
13. 另存后原文档和原素材库不变。
14. 同目录另存为、文档改名后，素材库照常可用。
15. 关闭 Photoshop 后，素材、文案、变体、附件都完整留在磁盘上。
16. 能导出一个不依赖素材库的交付版 PSD。
17. 同一资产的变体尺寸一致，切换变体时图层在画布上的范围不变；放大、扩图的结果是新资产、新图层，摆放位置正确。
