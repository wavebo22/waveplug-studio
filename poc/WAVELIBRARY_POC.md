## P0-1 嵌入转链接：通过

```js
// 必须同时给目标图层和保存路径；只给路径会报「命令"转换为链接对象"当前不可用」
{ _obj: "placedLayerConvertToLinked",
  _target: [{ _ref: "layer", _enum: "ordinal", _value: "targetEnum" }],
  using: { _path: token, _kind: "local" } }
```

- 写出了 `WaveLibrary\asset_001_A\source.png`，图层变成链接，链接指向这个文件。
- 名称、混合模式、不透明度、剪贴、像素蒙版、矢量蒙版、图层样式、智能滤镜、变换四角坐标、变形全部不变。
- 合成画面转换前后逐像素比对：`maxDiff = 0`。
- 一步历史记录「将智能对象转换为链接对象」。
- 智能对象的内部 ID（`smartObjectMore.ID`）会变成新的。
- 另一种做法也可行：对**嵌入**对象直接执行 `placedLayerRelinkToFile`，它就变成链接到那个文件的链接对象（见 P0-2 c）。

## P0-2 复制图层与重新链接：**部分不通过**，需要改设计

| 测试 | 结果 |
|---|---|
| a. 链接图层 Ctrl+J 复制，重新链接副本 | 原图层**跟着变** |
| b. 嵌入图层复制（两者共享内容），把其中一个转为链接 | **只有这一个**变成链接，另一个仍是嵌入 |
| c. 对嵌入图层直接重新链接到另一个图层正在用的文件 | 可以，两者链接同一个文件 |
| d. 接 c，重新链接其中一个 | 另一个**跟着变** |
| e. 链接图层上执行「通过拷贝新建智能对象」 | 不可用（命令当前不可用） |
| f. 两个分别置入、原本无关的图层，先后重新链接到同一个文件，再改其中一个 | 另一个**跟着变**，之后一直绑在一起 |
| g. 两个图层分别链接 `source.png` 和它的 NTFS 硬链接 `source_hardlink.png`（同一份数据，不同路径） | **互相独立** |
| h. 嵌入其中一个（`placedLayerConvertToEmbedded`） | 同组的**全部**变成嵌入 |
| i. 接 h，在其中一个上执行「通过拷贝新建智能对象」，再把副本重新链接到另一个路径 | 副本**独立**，原来那组不受影响；副本保留变换、变形、蒙版、样式、智能滤镜，但**丢了剪贴蒙版**（要重新设置） |

结论：

- **Photoshop 按文件路径把链接图层分组。** 链接同一个路径的图层，重新链接其中任何一个，全部跟着变，而且一旦链接到同一路径就一直绑在一起。
- 所以「同一资产的两个图层各用各的变体」只在两者**链接不同路径**时成立。只要有一刻两个图层用了同一个变体文件，它们就会被绑定。
- 可行的绕过办法：同一份数据给不同图层不同的路径（硬链接，g 已验证；不支持硬链接的盘就复制一份）。
- 已经绑定的图层，要拆开只能走 h + i：整组先嵌入，复制出一个独立副本，再链接回去。大文件时很慢，副本是新图层（ID 变了），剪贴蒙版要补设。

对 6.3「只转换这一个」的影响是好消息：嵌入的复制图层可以一个一个单独转（b），不需要先「通过拷贝新建智能对象」。「全部转换」做法：转换其中一个，再把其余几个重新链接到同一个文件（c）。

## P0-3 撤销与历史记录：通过（插件里待复核）

- 连续 5 次重新链接后，在历史记录里往回跳 1、2、3 步再跳回最新：每一步每个图层的链接路径都准确回到当时的状态，`executeActionGet` 立刻读到新路径。
- `executeAction("undo")` 也能撤销，但它是「还原 / 重做」切换，连续调用第二次报「还原当前不可用」。插件里用历史记录状态跳转更可靠。
- 要在插件里复核：UXP 里读到的路径是否同样立刻更新，以及能否收到历史变化事件来刷新变体栏。

## P0-4 同尺寸重新链接：通过

- 在 A.png、B.png、`source.png` 之间重新链接多次，变换四角坐标始终是 `[914.77, 564.02, 1378.41, 688.25, 1285.23, 1035.98, 821.59, 911.75]`，一位小数都没变。
- 隐藏其他图层后，和转换前的合成画面逐像素比对：`maxDiff = 0`。

## 顺带看到的（P1-5 预备）

- 重新链接到 2 倍大的 `C_2x.png`：Photoshop 保留**缩放百分比**，图层在画布上以中心为基准**放大成 2 倍**（四角 `[729.53, 328.03, 1656.82, 576.5, …]`）。所以放大当前图层时，新图层要再缩小到 1 / 倍数才能和原图层重合。
- 链接回原尺寸文件后，四角坐标恢复原值。

## P1-5 放大当前图层：通过

- 原图层：链接 `A.png`（800×600），缩放 60%、旋转 15°、平移，正片叠底 70%，描边，羽化 30px 的像素蒙版，剪贴到 `base`。
- 置入 2 倍大的链接文件 `C_2x.png`（1600×1200）作为新图层，放在原图层正上方，然后：
  - 按原图层四角坐标算出缩放（宽高分别算）、旋转角度和中心点，用 `resize` / `rotate` / `translate` 摆放。新图层四角坐标和原图层**完全一致**（两位小数）。
  - 混合模式、不透明度直接设置；样式用「拷贝图层样式 / 粘贴图层样式」（`CpFX` / `PaFX`）；像素蒙版用「新建通道，位置 = 本图层蒙版，来源 = 原图层蒙版」复制；剪贴蒙版直接设置。全部成功。
  - 整个过程包进 `suspendHistory`，只占一步历史记录「WavePlug 放大图层」。
- 隐藏原图层后和原画面比对：最大差值 43，只有 1688 个通道像素差值大于 2（总共 900 万个），都在色块边缘，是 2 倍图缩小显示和原图的重采样差异，位置没有偏移。
- 没有做的：**变形**（warp）和**智能滤镜**没有复制到新图层，原图层有这两样时要提示用户。算法假设原图层没有斜切（这次斜切角 0°），有斜切时要另外处理。

## P1-6 扩图：通过，但置入位置要手动校正

- 2000×1500 的画布，四边扩展 左 200、上 100、右 300、下 0：两次 `resizeCanvas`（先以右下为锚点扩左上，再以左上为锚点扩右下），画布变成 2500×1600。
- 在最上方置入 2500×1600 的链接文件，加接缝蒙版（中间原图区域内缩 24px、羽化 24px 后反选）。整个过程包进 `suspendHistory`，**一步历史记录**「WavePlug 扩图」。
- **问题**：置入后的位置不在画布正中，四角是 `[-102.5, 0, 2397.5, 0, …]`，横向偏了 102.5 像素。用 `translate` 校正后变成准确的 `[0, 0, 2500, 0, 2500, 1600, 0, 1600]`。
- 所以实现时顺序必须是：**置入 → 按四角坐标校正位置 → 再加蒙版**。这次是先加蒙版再校正，蒙版跟着图层一起移动了。

## P1-7 像素图层原地转成链接智能对象：方法 B 通过

测试图层 `px`：两个色块 + 黑色标记，描边，羽化 40px 的像素蒙版，强光 80%，剪贴到 `base`，上方还有一个图层。

| 方法 | 结果 |
|---|---|
| A. 直接「转换为智能对象」（`newPlacedLayer`）再转链接 | **不行**。蒙版和样式被收进智能对象内部，外面的图层上没有了；不透明度变成 100%；画面最大差值 12。蒙版、样式会被烘焙进素材文件，之后切换变体会被一起替换 |

## P1-10 重新链接耗时：本地盘已测，网络共享未测

画布 3000×2000，一个链接图层在同尺寸的两个文件之间来回重新链接，每次计时包含 `app.refresh()`（画面刷新完成）：

| 文件 | 大小 | 三次耗时（秒） |
|---|---|---|
| 4K PNG（3840×2160，带噪点） | 24 MB | 1.71、1.58、1.57 |
| 8K PNG（7680×4320，带噪点） | 94 MB | 2.89、2.88、2.86 |

## P2-13 色彩：通过，有一点要注意

- 16 位 ProPhoto RGB 的内容嵌入到 8 位 sRGB 文档，再转成链接：导出的 `source.psd` 仍是 **16 位 ProPhoto RGB**，没有被转换成宿主文档的色彩。

## P0-3、P2-12 插件里的事件：通过

开发版加了临时探针（`src/ps/libraryProbe.ts`，提交 29e8fa7，测完已删除），监听 `save`、`close`、`open`、`historyStateChanged`、`placedLayerRelinkToFile`、`placedLayerConvertToLinked`，收到时用只读 `smartObject` 属性的 `get` 读当前图层的链接路径，写进 `uxp_runtime.log`。

**先发现的一点**：通过 MCP（ExtendScript）执行的打开、重新链接、历史记录跳转、保存、关闭，插件**一个事件都收不到**，连平时打开文档必有的面板刷新记录也没有。所以这两项由用户在 Photoshop 界面里手动操作（2026-11-17 14:29~14:33）。这也说明：以后用 MCP 测插件相关的行为，结果不可信，要在界面里操作。

| 操作 | 插件收到的 | 读到的链接 |
|---|---|---|
| 打开 `proj.psd` | `open`（带路径、`documentID`）+ `historyStateChanged`（"Open"） | 正确；打开后第一次读取 807 ms，之后都在 0~4 ms |
| 重新链接到文件 | `placedLayerRelinkToFile`（带新路径、`layerID`）+ `historyStateChanged`（"Relink to File"） | 新路径 |
| Ctrl+Z、Ctrl+Shift+Z、在历史记录面板点「打开」和最后一行 | 每次一条 `historyStateChanged`（带状态名和 `itemIndex`） | 每次都准确对应那个状态（「打开」= `v0001.png`，「重新链接」= `source.png`）；从事件到读完 47~83 ms |
| Ctrl+S | 两条 `save`：`saveBegin`、`saveSucceeded`，都带 `in`（路径）和 `documentID` | — |
| 存储为 `proj_手动.psd` | 两条 `save`，`in` 是新路径，`as` 是格式；`saveSucceeded` 时 `doc.path` 已经是新路径 | — |
| 关闭 | `close`，**只有 `documentID`**，事件到达时文档已经不在了 | 读不到 |

结论：

- **P0-3 在插件里复核通过**：撤销、重做、历史记录跳转后，插件立刻能读到正确的链接路径，「当前变体从链接路径读」（规格 7.1）成立，变体栏可以在 0.1 秒内刷新。
- **P2-12 通过**：保存、另存为能拿到文档 ID 和路径；`saveSucceeded` 里 `in` 和原路径不同，就是「另存到其他位置」（规格 2.4）。关闭事件只有 `documentID`，所以插件要在 `open` / `save` 时自己记下「文档 ID → 路径」，关闭时据此找到素材库，弹回收站提示、写 `documents[].uses`（规格 7.5）。
